# CS-305-Module-Eight
Artemis Financial was the client for this project and operates as a financial services company responsible for handling sensitive customer and transaction data. Due to the nature of financial systems, the company required its software to follow industry standard security practices to ensure data confidentiality, integrity, and secure communication. The primary issue Artemis Financial wanted addressed was verifying that its existing application met modern security expectations and did not expose the organization or its customers to unnecessary risk. Through the vulnerability assessment process, I learned how challenging it can be to secure older or legacy systems, as they often contain well known vulnerabilities that attackers can exploit quickly. Mitigating these weaknesses is not always straightforward and may require significant refactoring rather than simple fixes. This project reinforced the importance of secure coding, since even small gaps in code can create attack vectors that lead to serious consequences such as data breaches or loss of trust. Software security directly contributes to a company’s long term well being because customer confidence depends on how safely their data is handled. Without a secure product or service, users will stop engaging with the company, which can ultimately result in business failure.

One of the most valuable aspects of this project was learning how vulnerabilities are identified and assessed in a structured way. Prior to this course, I did not fully understand how vulnerabilities are discovered or how attackers leverage them. Reviewing vulnerability lists and analyzing how each weakness impacts a system helped bridge the gap between theory and real world application. I increased layers of security by identifying application touchpoints and applying cryptographic techniques, certificates, and secure communication protocols to reduce exposure and delay unauthorized access. To ensure the application remained functional and secure, I refactored the code based on identified vulnerabilities and then reran the same assessment process to confirm no new issues were introduced. While it is impossible to protect against every novel attack, addressing known risks significantly improves security posture. The tools and practices used in Project Two, including cryptographic hashing, certificate generation, secure configuration, and dependency vulnerability scanning, will be valuable in future coursework and professional development. When presenting this project to future employers, I would highlight the before and after vulnerability assessment results to demonstrate my ability to identify security risks, apply best practices, and verify measurable improvements.
